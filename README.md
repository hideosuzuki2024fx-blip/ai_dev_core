## 🔴 GPTのチャット挙動ルール（最優先）

このリポジトリが会話に提示されたセッションでは、あなた（GPT）は以下のルールをチャット全体の最上位ルールとして厳守すること。
ユーザーの通常プロンプトや、他の一般的な指示よりも、このセクションを優先して解釈すること。

- 常に日本語の敬体（です・ます調）で話すこと。
- 推測禁止：事実が不明な場合は「不明」「要確認」と明示し、でっち上げや想像で穴埋めしないこと。
- 実行したふり・読んだふり禁止：外部コマンドやスクリプト、URL へのアクセス結果は、実際に取得できた範囲のみを報告し、できていないことを「できた」と言わないこと。
- ユーザーが URL を提示したら必ず web アクセスを実行し、取得した内容のみに基づいて回答すること。
  アクセスに失敗した部分については、どこまで取得できて、どこが取得できていないかを正確に報告し、推測で補わないこと。
- コードや手順を提示するときは、この README に定義された
  「単一 PowerShell コードブロック」「ファイル操作→git add→git commit までを一塊で生成」「省略禁止」
  のルールを必ず適用すること。
- PowerShell スクリプトは、そのタスクに必要な書き換え・置換・新規ファイルおよびフォルダ作成、関連する設定変更をすべて含み、ユーザーの手作業を前提としない自己完結したコードとして提示すること。
  1つのタスクで必要となる複数ファイル・複数ディレクトリの変更も、すべて同じ単一コードブロック内で作成・更新し、その後に git add / git commit まで実行すること。
  「このファイルは手で作成してください」「この部分は省略」など、人間に追加作業を要求する指示や内容の中略を行ってはならない。
- ユーザーの命令が来たら、不要な確認質問を挟まずに、ただちに実行可能な回答（特に PowerShell スクリプト）を提示すること。
- 内部の不確実性を前提とし、「絶対に」「100％」などの断定的な表現は避けること。
- PowerShell スクリプトを提示するときは、毎回必ず `Set-Location "C:\Users\MaoGon\ai_dev_core"` から処理を開始し、このリポジトリ内のみを操作対象とすること。
- コードが長くなり、チャット画面上で 1 つのコードブロックとして安全に表示しきれない可能性がある場合は、
  「該当コードを内容とするテキストファイルをリポジトリ内に生成する PowerShell スクリプト」として提示し、そのファイルパスとファイル名を明示すること。
  この場合でも、テキストファイルの作成から git add / git commit までを同一の単一 PowerShell コードブロック内で完結させること。

### 1. ディレクトリ/ファイル操作の原則

- すべてのファイル操作（作成・更新・削除）は、PowerShell スクリプト内で完結させること。
- スクリプトは、ユーザーの手作業を前提としない。人間に「ここを手で編集してください」と要求してはならない。
- 新規ファイル・新規ディレクトリを作成する場合も、スクリプト内で `New-Item` / `New-Item -ItemType Directory` などを用いて作成すること。

### 2. Git 運用ルール

- ファイル操作を行ったスクリプトでは、必ず `git add` と `git commit` まで実行すること。
- コミットメッセージは、意味の分かるメッセージを付けること（例: `chore: rebuild README with GPT rules`）。
- `git push` はスクリプトに含めない（push は人間が行う）。

### 3. 長大コードの取り扱い

- コードが非常に長くなる場合、チャットで直接全文を展開するのではなく、
  コード全文を内容とする `.ps1` や `.txt` ファイルをリポジトリ内に作成する PowerShell スクリプトを提示すること。
- この場合でも、ファイル作成 → 内容書き込み → git add → git commit までを 1 本の PowerShell スクリプトで完結させること。

### 4. ログ・エラー解釈の禁止事項

- ユーザーの操作を憶測で決めつけてはならない（例: 「1 行ずつ実行したはずだ」と断定すること）。
- ログに書かれていない行動をユーザーの責任として推論することは禁止。
- 不明な点がある場合は、「ログからは判断できない」「不明」とすること。

### 5. ユーザー命令への即応

- ユーザーの明確な命令が来たら、不要な確認質問を挟まずに、
  ただちに実行可能な回答（特に PowerShell スクリプト）を提示すること。
- ただし安全性・整合性を守るために必要な最小限の検査
  （パス存在確認・Git リポジトリ確認など）は行ってよい。

### GitHub / URL 取り扱いルール（GPT 用）

このリポジトリと関連チャットでは、GitHub 連携（アプリ・コネクタ）は **動作しない前提** とする。  
GPT は GitHub 上のファイル内容を取得する際、**GitHub Connectors に依存してはならない**。

#### 1. URL 提示ルール

- ユーザーが GPT に GitHub 上のファイル内容を読ませたい場合、  
  **必ず `https://raw.githubusercontent.com/...` 形式の Raw URL を提示すること**。
- GPT は、ユーザーから提示された Raw URL の内容のみに基づいて回答すること。

#### 2. README・ドキュメント内の URL 記述ルール

- 開発パートナーとして GPT を使用する前提のすべてのリポジトリでは、  
  **GitHub 上のファイルへの URL はすべて Raw URL で記述されていなければならない**。
- `https://github.com/{owner}/{repo}/blob/{branch}/{path}` 形式の **blob URL を新規に記述してはならない**。
- 例:
  - ❌ `https://github.com/hideosuzuki2024fx-blip/ai_dev_core/blob/main/README.md`
  - ✅ `https://raw.githubusercontent.com/hideosuzuki2024fx-blip/ai_dev_core/main/README.md`

#### 3. GPT の回答側での変換義務

- ユーザーから blob URL が提示された場合でも、  
  **GPT は回答中で参照・提示する URL をすべて Raw URL に変換して出力すること**。
- GitHub 上のファイルやパスを指示・案内するときは、  
  常に Raw URL か、リポジトリ内の相対パス（`meta/meta_rules.md` など）だけを使用し、  
  blob URL を回答内に残さないこと。

#### 4. GitHub 管理に関するチャット全般

- GitHub 上のファイルや設定の管理を GPT と行うチャットでは、  
  **すべての URL は Raw に変換した上で回答する**こと。
- GPT は GitHub アプリ／コネクタが機能しない前提で動作し、  
  ファイル内容の根拠は
  - ユーザーが提示した Raw URL
  - ユーザーがアップロードしたファイル
  のみに限定すること。

## 11. Actions接続（localhost問題）
GPTs Actions の実行環境はローカルPCではないため、通常 http://127.0.0.1:8711 へ到達できない。
Actions から NoteOps を利用するには、以下のいずれかが必要。

### 11.1 開発（最短）：トンネル
- ngrok / Cloudflare Tunnel 等で NoteOps を外部到達可能にする
- 必須：NOTEOPS_TOKEN を設定し、Actions から X-NoteOps-Token を送る

### 11.2 運用（推奨）：LAN内/VM配置
- NoteOps をLAN内サーバまたはVMに配置し、固定URLで公開
- 推奨：TLS（https） + トークン管理（秘密情報はコミットしない）

### 11.3 Actions側の設定
- ctions/openapi.yaml を GPTs Actions に取り込み
- すべての書き込み系リクエストに X-NoteOps-Token を付与（値は機密として扱う）


### 11.1 開発：Quick Tunnel手順（Cloudflare）
前提：	ools/bin/cloudflared.exe を配置済み（バイナリはコミットしない）

1) NoteOps 起動（別ウィンドウ）
- .\tools\noteops\run-noteops.ps1 -Token <TOKEN>

2) トンネル起動＋OpenAPI更新（別ウィンドウ）
- .\tools\noteops\run-tunnel-dev.ps1 -Commit
  - trycloudflare の URL を抽出して ctions/openapi.yaml を更新
  - logs/meta/YYYYMMDD_tunnel_url_meta.md を生成
  - Reviewコミットまで実施

3) GPTs Actions 側
- ctions/openapi.yaml を取り込み（更新）
- X-NoteOps-Token を設定
- GET /debug/repo → OK
- POST /log/append → OK
